# Preserve EDA scope and explain governed recovery

## Problem

Run `run_ac252bfd659a443499700ec43caf2163` received the literal dataset answer `german_credit`
without the preceding EDA request in its explicit clarification context. THY subsequently planned
training. Intake filled the profile from project context, but execution classification escalated to
review without attempting a useful question. The terminal diagnostic attached a recovered pandas
error to an independent confinement finding and exposed no recorded remediation recommendations.

## Decision

Recover a missing continuation flag only for an exact declared dataset name following an adjacent,
completed Auto clarification by the same actor in the same project. Validate the existing complete
parent chain and freeze only human messages. Preserve strict handling of unrelated, legacy,
oversized, Ask and already executed work. Intake and downstream planning use the scoped human request.

Extract classification persistence from the large interview service into `risk_classification.py`.
The measured service shrinks from 722 lines and 26 methods to 707 lines and 25 methods; its broader
size/cohesion flags remain existing debt rather than a claim of complete refactoring.
After a classification still requiring review, use the existing routed, bounded question selector
with the execution classifier's role. A model may select an answerable fact or declare no useful
question; it cannot authorize execution or lower risk. Persist the selection against its exact
classification event, including a null selection, and reuse pending questions after reconstruction.
Retain per-field, total-interview and uncertainty-round limits and the Gate-owned information wait.
No useful question or unavailable provider leaves the existing review requirement intact.

Project recorded recommendations only from the audit snapshot bound to the closing decision.
For A19 partial confinement, display the recorded unenforced limits rather than a computation error
on the referenced tool event. A chat action prepares an Ask draft; the user submits it, existing
drafts remain intact, and no Run is started automatically. A blocked Run's immutable outcome stays
unchanged; a corrected work request creates a separately governed turn.

Give audit producers an explicit in-flight/final boundary, the validated declared profile and
recorded approvals. Accept Run-event references only from the evidence exposed by the final
bounded prompt, while retaining the applicable-regulation tool evidence path. Positive compliance
statements are not adverse findings; dataset columns do not establish model-feature use and
tool approvals do not establish all consequential oversight. Feed accumulated candidates back
to discovery producers while keeping the independent critic's original snapshot and deterministic
report. Preserve deterministic findings and the existing critical-finding policy.

Keep projection assembly in its own module so the audit runner no longer crosses the module-size
threshold. Give the compact audit context and verified excerpts explicit priority before long
narrative messages; canonical top-level key sorting would otherwise hide the new context in the
real incident. Preserve deterministic serialization of values and the total character budget.
Legacy reports omit the new default audit mode when it was absent at load time, preserving exact
assurance JSON and digest checks without weakening comparisons or rewriting evidence.

## Alternatives considered

- Trusting the model's continuation flag alone reproduced the lost scope in a real session.
- Carrying every preceding request could revive abandoned or already executed work.
- Asking a fixed interview again wastes known facts; skipping all clarification on a complete
  profile ignores uncertainty introduced by the execution classifier.
- Automatically treating sensitive data as low risk, approving work, or disabling critical-finding
  rules would change authorization rather than correct context.
- Reopening a terminal blocked Run would require a separate lifecycle contract and fresh audit
  binding; an explicit new governed turn preserves the existing architecture.
- Treating model-authored findings as proven facts, or accepting citations to events the model
  never received, would perpetuate unsupported conclusions rather than correct their evidence.

## Consequences

The change preserves public standalone Run behavior and adds only optional diagnostic fields.
Stored model responses, Run events, approvals and artifacts are not rewritten. Model interpretation
and question quality remain probabilistic; tests use scripted providers and native temporary
persistence. The live incident was verified read-only, including artifact hashes on an isolated copy.
Independent review covers ownership, retries, model routing, scoped questions and diagnostic controls.
